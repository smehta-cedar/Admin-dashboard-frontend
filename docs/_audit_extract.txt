Frontend Audit — Sep 2026
2026-09-18  ·  @Someone
The monthly-commission frontend ( main  at d75592f) builds and typechecks clean. The
reference-data pages are solid and well specified; the commission workflow itself does
not exist yet, and the pages that feed it disagree with each other in a few places.
Everything below is design and logic, not compile errors.
Top view
What is here: a well-built reference-data app (Agents, Carriers, Contracts, Logins, Users,
Agency) with consistent server-only data boundaries, automatic change notes, and a
thorough spec in docs/entity-page-pattern.md .
What is not here: the commission workflow the repo is named for. Overview  renders a
fake matrix from lib/commissions.ts , which has its own carrier list keyed by codes
( HUMANA , UHC ) that never touches data/carriers.json  IDs. Rulebook  is an empty
state. Nothing imports a statement or matches rows to agents. The matching keys were
clearly designed for that step (agent aliases  “seen on statements”, login
writingNumber ) but nothing consumes them. Two carrier models exist today, Carrier
{code, name}  and CarrierRecord {id, …} , and they will have to be reconciled before
statements land.
The operational flow (add agent → licence states → carrier footprint → appointment →
login) exists, but the user has to discover the order:

Logic disruptions (verified)
1. Dialog closes on inside clicks. components/modal-dialog.tsx:41  now has p-6 , but
every form still carries its own p-6  ( agent-dialog.tsx:199 , agency-
dialog.tsx:171 , appointment-dialog.tsx:290 , user-dialog.tsx:218 , carrier-
dialog.tsx:200 ). The backdrop handler ( event.target === event.currentTarget )
fires on the 24px ring inside the dialog. Regression from commit 6212bf4 . Doc §8 still
documents p-0  and max-w-lg .
2. Inactive agents follow three different rules. Both Contracts pages drop them server-
side ( contracts/page.tsx:28 , by-carriers/page.tsx:25 ). The carrier profile shows
them ( carriers/[id]/page.tsx:42 ). The agent profile lets you appoint one ( agent-
profile.tsx:406 ), creating a contract no Contracts page can show or edit. Humana
reads “5 agents” on its profile and “4/4” on by-carriers.
3. “Appointed” means different things on the two Contracts pages. By-state counts
agents with at least one writable state ( contracts-view.tsx:217 ); by-carriers counts
any contract row ( carrier-contracts-view.tsx:150 ). Contract 13
( appointedStates: [] ) earns HealthSpring a 1/4 card while adding nothing to the
map.
4. data/users.json  breaks its own rules. User 1 has role: "agent"  and no agentId ;
the loader does not warn, and Edit cannot save him without linking an agent that does
not exist. Users 5 and 6 carry agentId  on non-agent roles and are dropped silently
( lib/users.ts:97 ). data/user-notes.json  describes a different users list (wrong
emails, wrong statuses).

5. Users edits never reach the session. UsersView  keeps users in React state;
getSessionUser  and the login page re-read JSON. Marking a user inactive or changing
a password has no effect on sign-in. Expected at dummy stage, but nothing in the UI
says so beyond the generic banner.
6. Appointment edit lets agent and carrier change ( appointment-dialog.tsx:310-
350 ), reassigning a contract’s identity while keeping its ID and note history. The by-
carriers hidden-row notice checks only the new carrier.
7. Entity dialogs disagree on validation. saveAgent  returns one error at a time (NPN,
then licence numbers); saveCarrier  returns all at once. Carrier alias uniqueness is
never checked, only the name, though lib/carriers.ts:35  says both. Save-result
shapes differ across saveAgent  / saveCarrier  / saveAgency  although the doc says
they match.
8. Smaller. Agent switcher goes stale on rename ( agent-profile.tsx:232  keeps server
order; the carrier one re-sorts). Carrier profile keeps two copies of the record in state
( carrier-profile.tsx:87-88 ). Licence-number note diff is order-dependent and
records the whole list for one changed number. agencyLicenseNumbers  is shown on
the by-state panel as a bare unlabelled number, contradicting the doc’s “not a
participant in contracts”. Orphan contracts (unknown carrier ID) are fabricated on by-
state and dropped on by-carriers.

and its notes fixtures; add a loader warning for an agent-role user with no agentId .

(largest wins first).
